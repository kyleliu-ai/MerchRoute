# v0.1.8：审核进度精简与 OZON 重复商品卡恢复

本版本集中交付两个已经分别提交的任务：隐藏审核工作台中的“审核与投递进度”卡片，以及修复 OZON 重复商品卡导致的无效重试与变体状态对账。两个任务共同使用一个 PR 和同一份候选运行包，不包含第三方依赖、n8n、Jimeng 或 PostgreSQL 版本升级。

## 用户可见变化

- 审核列表、审核详情、下载中心、待投递和投递历史不再显示“审核与投递进度”卡片；SSE 与低频回退刷新仍保留，真实处理结果继续在待投递和投递历史中呈现。
- 审核通过后的提示直接说明应前往“待投递清单”或“投递历史”查看结果，避免引导用户寻找已经隐藏的进度区。
- OZON 返回 `SPU_ALREADY_EXISTS_IN_ANOTHER_ACCOUNT` 时，页面明确显示“商品卡重复”、失败 Offer 及冲突 Offer，不再允许继续无效重试。
- 操作员可以先执行无副作用的平台状态同步，逐个回读变体状态；满足严格空闲和一致性门禁后，可以只终止 MerchRoute 本地自动流程。该操作不删除或修改 OZON 平台商品卡。

## 发布与安全边界

1. 应用根包、server、web、shared 及锁文件统一为 `0.1.8`。
2. 本版本不修改或部署 n8n 工作流；受控工作流仍为 36 个，原启用状态保持不变。
3. 候选验收必须覆盖完整单元测试、隔离 PostgreSQL 集成、完整 Playwright、Jimeng、部署契约、发布包启动与篡改检测、Gitleaks 和禁入规则。
4. OZON 验收只使用 mock API 与隔离数据库，禁止点击真实任务重试、创建商品、上传媒体、修改价格或库存。
5. 切换正式服务前必须确认采购、审核投递、WB/OZON 任务、重试、租约和 UNKNOWN 写入为空；使用同一份已验收候选包，不在 PR 合并后重新构建。
6. 正式切换只更新代码运行包和发布绑定，不恢复旧数据库、不清空业务状态；失败时保留现场并按兼容门禁回滚到上一运行包。

OZON 恢复协议详见 [OZON 自动上品：重试上品](../ozon-publish-retry.md)。
