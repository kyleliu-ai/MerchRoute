# v0.1.7：WB / OZON 受控重试发布契约

本版本集中交付 WB 与 OZON 自动上品的“重试上品”修复。两个任务分别提交、共同验收、使用一个 PR；版本号不等于已上线，实际状态必须回读发布记录与 About。完整保留先前 13 项功能组，加入本次两项，共 15 项。

## 必须配套的内容

- 应用与自身 workspace 为 0.1.7；不升级第三方依赖、n8n、Jimeng 或 PostgreSQL 版本。
- 应用迁移 `040_wb_manual_publish_retry` 和 `041_ozon_publish_retry` 增加持久化重试台账。迁移幂等，不能恢复旧数据库覆盖新业务事实。
- WB S001 `qYxi3PPmRm7tjK0E` 使用受控 `wb-publish-retry-v1.mjs` 补丁，只修改四个指定 Code 节点。不得直接以脱敏 JSON 覆盖真实工作流。
- OZON 使用已有 P002 的导入回查、图片修复及价格/库存续跑分支；核验受控版本一致，不重新投递旧任务。
- 继续保留 36 个受控工作流及 3 个部署包。全新安装全部停用；不得为了安装验收而启用工作流。

## 现有安装升级顺序

1. 只读比较本机权威内容与候选，按本机覆盖规则取得相应确认；回读运行包、端口、凭据配置位置及工作流版本。真实环境文件、数据库备份和原始工作流只存仓库外并限制访问。
2. 完整回归、Gitleaks、Windows / macOS CI、隔离切换与回滚演练全部通过后，发布同一份已验收资产，不在 PR 合并后重建。
3. 切换前确认采购、投递、WB / OZON 任务、两种新重试记录及租约均空闲。旧版本数据库尚无重试表时仅允许受控旧版本兼容；新版本缺表或状态不明必须失败。
4. 备份旧运行包绑定、启动入口、外部环境配置、生产数据库和 live S001。若旧服务已停止，明确记录 `expectedStopped`，不得伪造 PID 或省略数据库空闲检查。
5. 启动候选并完成两项迁移，WB 重试入口仍默认关闭。核验 About 的产品版本、真实包哈希、端口、前端资源和关键只读页面。
6. 在当前任务明确批准相关部署且 n8n 无活动执行时，将补丁应用到刚完整读取的 live S001；保存原始版本，保持节点 ID、连接、凭据绑定和启用状态不变。GET 回读全部内容及 versionId，报告修改前后版本；锚点不匹配时停止。
7. 仅已有启用状态的 S001 且四个节点、运行提交和协议版本都匹配时，才可按 WB 协议工具受控开启重试入口。全新安装或原本停用的工作流继续停用，入口保持关闭并在报告中说明。
8. 再次核对 36 个工作流、n8n / Jimeng / PostgreSQL 健康、运行 PID、桌面和开机启动入口。按钮显示和 HTTP 202 仅代表受理，不能报告真实商品已上架。

本发布验收禁止点击真实任务“重试上品”、创建商品、上传媒体、更新真实价格或库存。真实恢复必须另行指定店铺、SKU 和任务身份，UNKNOWN 写入必须先回查。

## 回滚边界

先关闭 WB 重试入口，再核对两种重试记录、任务、租约和平台未知写入。只有空闲且兼容条件通过，才能切回保留的上一运行包及匹配工作流；保留新迁移、重试台账、平台回执和业务记录。旧应用不认识的新 attempt 或未决写入必须先完成核对，不能通过恢复旧数据库或清空状态强行回滚。
